# 03. 제조공정 품질분석 및 모델 시나리오 실습

공개 제조공정 시뮬레이션 데이터 3,240건에 p-관리도와 Random Forest를 적용해 이상 구간과 불량 관련 변수를 살펴봤습니다. DMAIC 흐름을 학습하기 위한 분석이며 실제 개선 조치를 수행한 실적은 아닙니다.

## 문제와 접근

1. **정의·측정:** `DefectStatus`를 분석 대상으로 설정했습니다. 행 50개를 가상 로트로 묶어 불량 비율을 비교했습니다.
2. **분석:** 선형 상관관계와 Random Forest 변수중요도를 비교하고 관련 변수의 구간별 불량 비율을 확인했습니다.
3. **개선 시나리오:** 높은 `MaintenanceHours` 값을 낮은 구간의 중앙값으로 바꿨을 때 모델 예측이 어떻게 달라지는지 계산했습니다.
4. **관리 검토:** 이상 구간을 조사 대상으로 남기는 관리 규칙 초안을 검토했습니다. 실제 현장 적용에는 별도 실험과 기준 검증이 필요합니다.

## 원본 분석 기록

| 항목 | 기록 |
|---|---:|
| 분석 데이터 | 3,240건 |
| 기준 `DefectStatus=1` 비율 | 84.04% |
| 가상 로트 | 64개 × 50건, 마지막 40건은 관리도에서 제외 |
| 관리한계 이탈 | 4개 로트, 모두 하한보다 낮은 구간 |
| Random Forest 평가 ROC-AUC | 약 0.797 |
| `MaintenanceHours > 12` 구간의 데이터셋 불량 비율 | 95.97% |
| `MaintenanceHours ≤ 12` 구간의 데이터셋 불량 비율 | 73.90% |

![Observed group comparison](results/group_comparison.svg)

원본 모델 기록에서 해당 고시간 그룹의 입력을 6시간으로 치환했을 때 평균 예측 확률은 약 95.8%에서 73.7%로 변했습니다. 이것은 **예측 모델의 입력 변화에 대한 반응**이며 인과적 개선 효과가 아닙니다. 이번 환경에서 재실행한 결과는 약 95.8% → 73.8%였고, 결과를 별도 파일로 보존했습니다.

## 해석에서 주의한 점

- `MaintenanceHours`와 불량의 통계적 관계만으로 ‘유지보수를 줄여야 한다’고 결론 내릴 수 없습니다. 문제 설비라서 유지보수가 길었을 가능성 등을 구분할 수 없습니다.
- 원본의 시나리오 평가는 학습에 포함된 표본까지 사용합니다. 예측 확률의 보정, 실제 개입 효과 및 미래 성능을 검증하지 않았습니다.
- 원본의 ‘전체 개선 후 비율’은 낮은 구간의 관측 비율과 높은 구간의 모델 예측을 합친 값입니다. 실제 전후 측정치나 일관된 전체 모델 전후 비교가 아닙니다.
- 실제 시계열·생산 로트가 없어 행 순서를 가상 로트로 취급했습니다. 관리한계 이탈은 실제 공정의 이상 발생 시점을 뜻하지 않습니다. 전체 3,240건으로 중심선을 계산하고 완전한 64개 로트만 표시하는 원본 계산 방식을 유지했습니다.
- 관리도 하한보다 낮은 4개 구간은 ‘불량 급증’이 아닙니다. 표본 구성과 순서 효과를 먼저 조사할 대상입니다.
- 12시간 경계는 이 데이터의 개별 행 분석에서 정한 탐색 기준입니다. 이를 실제 로트 평균의 관리한계로 바로 적용할 근거는 검증하지 않았습니다.

## 품질관리 관점

지표 정의 → 이상 구간 확인 → 관련 변수 탐색 → 검증할 가설 정리의 과정을 보여줍니다. 수치가 관측값인지 모델 추정치인지 구분하고, 개선안의 효과를 판단하기 위해 필요한 추가 검증을 제시하는 데 초점을 두었습니다.

## 실행

[데이터 출처](../DATA_SOURCES.md)의 CSV를 `data/manufacturing_defect_dataset.csv`로 배치합니다.

```bash
cd manufacturing-defects
python 01_analysis.py
```

`figures/`에 그래프, `summary.json`에 해당 실행의 결과가 생성됩니다.

- [분석 코드](01_analysis.py)
- [원본 결과 요약](results/source_summary.json)
- [재실행 결과 요약](results/reproduced_metrics.json)

코드의 `control_rule` 등은 원본의 탐색적 제안으로 남겨두었으며 검증된 운영 기준을 의미하지 않습니다.
